# M5-01: WSJT-X UDP protocol core (`hamq/core/wsjtx.py`) and packet fixtures

**Milestone:** M5
**Status:** done
**Skills:** wsjtx-udp (adif for the Logged ADIF payload)

## Goal
A pure Python decoder for the WSJT-X UDP messages HamQ listens for (Heartbeat, Status,
Close, Logged ADIF; everything else is "other"), an encoder for tests and tools, and
golden packet fixtures. It implements the "core/wsjtx.py" section of
`docs/ARCHITECTURE.md`.

## Scope
Files that may be created or changed:
- `hamq/core/wsjtx.py`
- `tests/core/test_wsjtx.py`
- `tests/fixtures/wsjtx/*` (synthetic packets, generated `README.md`, `captured/`)
- `scripts/make_wsjtx_fixtures.py`
- `tasks/M5-01-wsjtx-core.md`

## Out of scope
- `net/wsjtx_listener.py` (`QUdpSocket`), the dock, and writing QSOs to the GeoPackage.
- Parsing the ADIF text (`core/adif.py`).
- `CHANGELOG.md` (not edited in this parallel run, see Notes).
- Translation catalog: the module has no user-visible strings. The `ValueError` and
  `TypeError` messages are for programmers.

## Checklist
- [x] Wire layout checked against the upstream sources (see Result): header,
      Heartbeat, the full Status field list, Close, Logged ADIF, QDateTime, and
      JTDX's own Status layout
- [x] Public names exactly as in the contract: `MAGIC`, `HEARTBEAT`, `STATUS`,
      `QSO_LOGGED`, `CLOSE`, `LOGGED_ADIF`, `decode`, `Writer`, `encode_heartbeat`,
      `encode_status`, `encode_close`, `encode_logged_adif`. The only extra public
      item is an optional keyword argument, `encode_logged_adif(..., *, latin1=False)`
- [x] `decode()` never raises. Status always has `freq_hz`, `mode` and `dx_call`,

## Result

**Upstream verification.** Copies of the sources are in the session scratchpad
(`wsjtx/`). SourceForge `wsjt/wsjtx`, branch `master`, fetched 2026-09-29:
`Network/NetworkMessage.hpp`, `Network/NetworkMessage.cpp`,
`Network/MessageClient.cpp`, `UDPExamples/MessageServer.cpp`, `logbook/logbook.cpp`,
`widgets/logqso.cpp`, `widgets/mainwindow.cpp`. `logbook.cpp` was also fetched at tag
`wsjtx-2.7.0`, where `QSOToADIF` is identical. JTDX (`jtdx-project/jtdx`, GitHub
master): `MessageClient.cpp`, `MessageClient.hpp`, `NetworkMessage.hpp`, `main.cpp`,
`mainwindow.cpp`, `logqso.cpp`, `Radio.hpp` (copies from the fix round are in
`review_wsjtx/up/` and `fix_wsjtx/`). `MessageClient.cpp` on master was last changed
on 2022-02-14, and branch `jtdx_32a` has the same Status code.
- **Header.** `NetworkMessage::Builder` writes `quint32` magic `0xadbccbda`,
  `quint32` schema, `quint32` type and `id.toUtf8()` (QByteArray). The stream
  version is `Qt_5_2` for schema 2 and `Qt_5_4` for schema 3. The reader rejects a
  wrong magic and any schema above 3.
- **Heartbeat.** `Builder::schema_number` (3), `version.toUtf8()`,
  `revision.toUtf8()`. JTDX omits the revision. Clients start at schema 2 and move to
  a higher schema only after a server replies with it, so a listener that never
  replies receives schema 2.
- **Status** (`MessageClient::status_update`, 21 fields): quint64 dial frequency,
  mode, DX call, report, Tx mode, bool Tx enabled, bool transmitting, bool decoding,
  quint32 Rx DF, quint32 Tx DF, DE call, DE grid, DX grid, bool Tx watchdog, sub-mode,
  bool fast mode, quint8 special operation mode, quint32 frequency tolerance, quint32
  T/R period, configuration name, Tx message. The strings are utf8.
  `MainWindow::statusUpdate` sends `quint32_max` for frequency tolerance and T/R period
  when they do not apply, and a null QString for the sub-mode of FT8. The reference
  server (`MessageServer.cpp`) accepts a short Status (`ReadPastEnd` counts as
  "Short", not "Fail").
- **JTDX Status** (`MessageClient::status_update` on both branches): the WSJT-X
  fields up to fast mode, then `bool tx_first` (`<< fast_mode << tx_first;`), and
  nothing else. The frequency is `Frequency` = `quint64` (`Radio.hpp`), as in WSJT-X.
  Rx DF and Tx DF are `qint32` (spin box values, never negative).
  `MainWindow::statusUpdate` always passes a null sub-mode and `fast_mode` false.
  With the WSJT-X layout the `tx_first` byte would be read as `special_op_mode`,
  where 1 means "NA VHF". JTDX's id is `QApplication::applicationName()`: `JTDX`, with
  ` - <rig>` added by `--rig-name` and ` - test` by `--test-mode` (`main.cpp`).
- **Close.** The header only.
- **Logged ADIF.** One QByteArray:
  `"\n<adif_ver:5>3.1.0\n<programid:6>WSJT-X\n<EOH>\n" + record + " <EOR>"`. The
  record comes from `LogBook::QSOToADIF`, which counts lengths with `QString::size()`
  and returns `t.toLatin1()`. `size()` counts UTF-16 code units: one per character,
  two for a character above U+FFFF. `toLatin1()` works unit by unit, so such a
  character becomes `??` (checked with Qt 5.15.3, 5.15.15, 6.8.2 and 6.10.2). JTDX
  builds its record with `QString::length()` (the same count) and
  `myadif.trimmed().toUtf8()`.
- **QDateTime** (`NetworkMessage.hpp` comment; checked with Qt): `qint64` Julian day,
  `quint32` ms since midnight, `quint8` spec (1 = UTC), and a `qint32` offset only
  for spec 2. Qt 6.10 writes `00 00 00 00 00 25 8e 73 04 07 1c d8 01` for
  2026-09-15 18:46:15 UTC.
- **QDataStream types** (probed with PyQt): a null QByteArray is `ff ff ff ff` and an
  empty one is `00 00 00 00`. `bool` is 1 byte, and any non-zero byte reads as true.
  Qt_5_2 and Qt_5_4 give identical bytes for all these types.

**What changed**
- `hamq/core/wsjtx.py` (new, stdlib only: `struct`, `datetime`, `typing`).
  - `_Reader` checks every length against the bytes left before slicing, and raises
    a private `_Truncated`; `decode()` catches it. A declared length of about 4 GiB
    returns `None` in microseconds with no allocation.
  - Strings are decoded as UTF-8, falling back to Latin-1.
  - The Status layout is chosen by the client id (`_status_fields`): JTDX's for an
    id that starts with `JTDX`, WSJT-X's otherwise. `decode()` and `encode_status()`
    use the same choice.
  - `decode()` gets its input as plain `bytes` from `_datagram_bytes`, where only
    the built-in code of `bytes`, `bytearray` and `memoryview` runs. Plain `bytes`
    are used as they are. `bytearray` and `memoryview` are copied. A `bytes` or
    `bytearray` subclass is copied by its base class's own slice code, so none of
    its methods (`__bytes__`, `__buffer__` in Python 3.12+, `__getitem__`, `__len__`,
    `__iter__`) is called. The type comes from `type()`, so an object that only
    claims to be `bytes` through `__class__` gives `None`. So does a released
    `memoryview`.
  - `Writer` methods, all chainable: `header(msg_type, client, schema=2)`, `u8`,
    `boolean`, `u32`, `i32`, `u64`, `i64`, `double`, `byte_array`, `utf8`, `latin1`,
    `qdatetime`, `getvalue`. `boolean` accepts only `bool`. `latin1` converts one
    UTF-16 code unit at a time like `QString::toLatin1()`, so a character above
    U+FFFF becomes `??`. `utf8` raises `UnicodeEncodeError` (a `ValueError`) for a
    lone surrogate.
- `scripts/make_wsjtx_fixtures.py` (new). It writes the 11 synthetic `*.bin` files and
  `README.md`. `--check` compares without writing. `--verify-qt` rebuilds every packet
  with Qt's `QDataStream` and Qt's own text conversion (`QTextCodec` in Qt 5,
  `QStringEncoder` in Qt 6), statement by statement after the WSJT-X C++ code (JTDX's
  for the JTDX packets). It also compares hamq's UTF-8 and Latin-1 conversion and the
  script's ADIF length count with Qt's for 5 probe texts: Latin-1, Serbian Latin and
  Cyrillic, one and two emoji, and empty. ADIF lengths are `QString::size()`
  (`qstring_size`, UTF-16 code units). With both options, each check reports on its
  own; the exit status is 1 when either fails.
- `tests/fixtures/wsjtx/`: `heartbeat_schema2.bin`, `heartbeat_schema3.bin`,
  `heartbeat_jtdx.bin`, `status_ft8.bin`, `truncated_status.bin`, `status_jtdx.bin`
  (JTDX layout, `tx_first` true), `close.bin`, `logged_adif.bin` (UTF-8, NAME
  `Đorđe`), `logged_adif_latin1.bin` (as WSJT-X sends it, NAME `Jürgen`),
  `qso_logged.bin`, `bad_magic.bin`, the generated `README.md` (with a JTDX
  section), and `captured/` (8 real datagrams + `README.md`).
- `tests/core/test_wsjtx.py` (new, 217 tests, about 1 s).

**Behaviour choices the callers should know** (`net/wsjtx_listener.py`, dock)
1. Call `decode(bytes(datagram.data()))`. It returns `None` or a dict, and never raises.
2. Every string value, including `client`, can be `None`: a null string on the wire.
   Real WSJT-X sends `dx_call=None` before a DX call is set. `adif` can be `None` too.
3. Status holds only the fields that were present. Only `freq_hz`, `mode` and
   `dx_call` are guaranteed, and `freq_hz` is 0 when no rig is configured.
   `frequency_tolerance` and `tr_period` are `0xFFFFFFFF` when they do not apply.
   A JTDX Status (client id starting with `JTDX`) ends with `fast_mode` and
   `tx_first`. It never has `special_op_mode`, `frequency_tolerance`, `tr_period`,
   `configuration_name` or `tx_message`, so use `msg.get(...)` for those keys.
4. Heartbeat `revision` is `None` when missing (JTDX) or null. A Heartbeat without
   `max_schema` and `version` (only very old clients, which cannot send Logged ADIF)
   gives `None`, although upstream says to assume schema 2 in that case.
5. Schemas other than 2 and 3 give `None`. Type 5 (QSO Logged) is `"other"`; use
   Logged ADIF (type 12).
6. `encode_status` writes the optional fields in wire order up to the last one given.
   Earlier fields that were not given get defaults: `""`, `False`, 0 for
   `special_op_mode`, `0xFFFFFFFF` for the quint32 fields. It uses JTDX's layout for
   a client id starting with `JTDX`, like `decode()`. A keyword that the layout does
   not have raises `TypeError`: `tx_first` for WSJT-X, and `special_op_mode` or a
   later field for JTDX. So does a value of the wrong type, such as
   `tx_enabled="no"`. Encoders raise `ValueError` for schemas other than 2 and 3.
   `Writer.header` does not check the schema.

- For the orchestrator (the reviewer's point, outside this task). WSJT-X sends
  Logged ADIF (type 12) in Latin-1, so Serbian `č ć š ž đ` in NAME or COMMENT arrive
  as `?`. QSO Logged (type 5, "other" under the contract) carries the same text as
  correct UTF-8 (see `captured/wsjtx-2.7.0_qso_logged.bin`). A contract change that
  lets the listener decode type 5 and take NAME/COMMENT from it would keep Serbian
  names intact.
- For `core/adif.py` (parallel task). A WSJT-X Logged ADIF record has:
  - lowercase tags;
  - zero-length fields (`<rst_sent:0>`);
  - lengths from `QString::size()`, in UTF-16 code units: the number of characters,
    except that a character above U+FFFF (an emoji) counts 2. In WSJT-X's Latin-1
    record such a character arrives as `??`, so the count still matches the decoded
    text. JTDX sends UTF-8 with the same count, so after `decode()` an emoji is one
    Python character with a declared length of 2, and a parser that counts code
    points reads one character too many;
  - `FREQ` = dial + Tx offset with 6 decimals;
  - a double-spaced `COMMENT` when "report in comments" is on.

  The text reaches the parser as `str` that `decode()` already turned from Latin-1
  into Unicode. `tests/fixtures/wsjtx/captured/wsjtx-2.7.0_logged_adif.bin` is a
  real sample.
